# 赛道三方向一冲刺审计

## 提交前 P0 闸门

1. 从 `.env.competition.example` 生成部署环境变量，替换两项随机密钥和百炼 API Key/工作空间地址。
2. 保持 `COMPETITION_MODE=true`。该模式会拒绝模拟供应商、非 Qwen 模型和非阿里云百炼兼容地址。
3. 执行 `npm run competition:preflight`、`npm run typecheck`、`npm test`、`npm run eval`、`npm run build`。
4. 在真实百炼凭证下跑一次完整演示：表达近况 → 形成认识 → 后续调用认识 → 用户纠正 → 认识更新并可追溯。
5. 提交前确保 Git 工作区干净，再执行 `npm run package:source`；脚本会拒绝把未提交变化漏出源码包。

## 更好的切入方向

不要把主叙事做成“通用聊天产品”。用一个可量化的长期关系闭环作为十分钟演示主线：认识写入准确率、后续命中率、纠错生效延迟、旧结论撤回可追溯性、风险场景误触/漏触率。知微的差异点应落在“用户能看见、纠正并撤回 AI 对自己的认识”，同时展示画像、回复和反馈如何形成闭环。

## 团队衔接

- 云端 `main` 的直接记忆生命周期、批处理模型调用和新 UI 是基线，不回退。
- Character 对话继续走 Chat Completions；后台结构化任务继续走 Responses API。
- 演示负责人补齐真实百炼调用录屏、控制台资源/凭证截图和开源基线对照数据。
- 材料负责人将技术架构、闭环指标和风险边界压缩进不超过 30 页的 PDF。
