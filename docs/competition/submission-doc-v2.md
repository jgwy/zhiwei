4. **理解度分数**：代码为 **0–95 的整数百分制**（`min(95, round(95×覆盖×(0.35+0.30×验证+0.20×个性化+0.15×时效)))`），不应写成 0.73 小数；“3 轮后提升”“盲评偏好 >60%”等是验证目标而非已测得结果，已标注或删除。
5. **eval 语料位置**：11 条固定语料内嵌在 `packages/eval/src/run.ts`，不是 `packages/eval/src/corpus/`（该目录不存在）。
6. **0.72 阈值**：是后台反思阶段“新记忆提案与现有活动记忆的二元组重叠去重阈值”，不是 pgvector 向量相似度阈值。
7. **事实查证范围**：科学问题做 `science_claim_audit`；**时效事实类非科学问题也会 `buildFactBrief` 并保留来源**（只是不做科学审计）。“非科学问题不查证”不成立，已删。
8. **画像合成只使用已生效长期记忆**：pending 候选不参与画像/了解度；用户确认后才重算画像（与分支文档不变量一致），草稿示例中“基于 pending 记忆合成画像”已更正。
9. **回访**是“站内回访提醒（return note，≥6 小时生效、3 天失效）”，不是“问卷”；`question-planner` 是 onboarding 动态问卷，勿混淆。
10. **反思入队时机**：在回复流式生成完成、消息入库后入队（异步）；风险非 ordinary 回合不触发反思。
11. **普通陪伴回复规范**：system 中明确“通常 4–8 句、2–4 个自然段，复杂情绪可更长；不简单复述原文”等，不是只有“自然流畅+温度 0.58”；1200 是 `max_output_tokens`。
12. **结构化失败重试**：真实网关对结构化输出有“质量重试”契约（`aliyun-contract.test.ts` 断言失败后重试共 2 次调用），不是简单“重试 1 次”。
13. **P7 示例为示意**：标注“示意性脱敏示例，非某次真实运行输出”；科学输出 schema 按代码字段（`content / claimIndicesUsed / analogy{text,boundary} / distinctions`），不虚构字段。
14. **生涯话题**：用户明确求建议时，代码要求给“明确但可修正的意见”（dialogue-orchestrator），不是一律不给建议；医疗/法律/财务不给确定建议、健康不诊断，这两类表述已分开。
15. **模型名是工作空间配置值**：`.env` 默认 dialogue=`qwen-plus-character`、background=`qwen3.8-flash`、embedding=`qwen3.7-text-embedding`，review 分支演示脚本 dialogue=`qwen-flash-character`——这些是百炼工作空间部署 ID，避免被当成通用公开模型名。

### 作品简介（300字内，可直接粘贴）

知微是一款面向长期陪伴场景的 Web 端 AI 陪伴应用，目标是把“每次聊天都很友善、却始终没有积累出真正的了解”，变成一套可验证的长期记忆与画像系统。它用双轨记忆把“记住什么”与“能否使用”分开：短期信息只服务当前会话并到期过期；长期认识先由模型提出候选，经用户确认或编辑后才生效。对话会在后台沉淀为八维画像综述、理解度分数、心情与回访，并演化出只属于该用户的表达方式。区别于通用模型直接回答，知微让“温度”建立在机制上：画像不贴标签、不预测走向；所有表达先经风险分级与事实、科学审计，宁可承认不确定，也不以“像人”牺牲准确。系统基于 Qwen 系列构建，提供记忆查看、确认、编辑、撤回与全量删除，并完成端到端回归验证。

### Qwen 使用说明（300字内，可直接粘贴）

系统通过统一模型网关调用阿里云百炼的 Qwen 系列模型（工作空间部署 ID，OpenAI 兼容接口）。对话回复走 Responses 流式（默认 qwen-plus-character，演示脚本为 qwen-flash-character，temperature 0.58，最长 1200 token）；高情绪敏感回合、后台反思/画像合成/技能演化与科学写作走严格结构化输出（qwen3.8-flash，情绪 0.38、科学/写作 0.32）；向量检索用 qwen3.7-text-embedding。网关支持 scripted/replay/fault/aliyun-bailian 四种适配器，便于零成本回归与真实调用无缝切换。每次调用都记录任务、模型、传输协议、token、来源、延迟与费用估算（model_runs 等表），可审计、可复现。

### 本作品核心主张

- **选题维度**：以 A（数字分身 / 长期陪伴）为主，并用事实审计与表达分寸覆盖 B（让 AI 更有人味）与“科学事实准确传达”的考察要求。
- **服务对象与场景**：需要被长期了解的普通匿名用户（cookie 会话隔离）；典型场景为日常陪伴聊天、情绪倾诉与倾听、科普式科学问答、课程讲稿式写作。不面向专业医疗、心理、法律或生涯决策场景。
- **最有代表性的结果 1（理解用户）**：系统以 8 维动态画像 + 理解度分数（覆盖/验证/个性化/时效四分量）量化“越来越懂用户”；固定语料下 ScriptedAdapter 记忆分类 F0.5=1、检索召回@8=1、风险分类准确率=1（口径见 `docs/evidence/competition-baseline.json`，2026-09-02）。开发面板可查看记忆版本、画像快照与理解度分量；用户确认/编辑候选后画像更新，下一轮对话即可体现。⚠️【待补】真实多轮演示的“理解度随时间上升”截图与说明。
- **最有代表性的结果 2（可靠与可控）**：三层事实核对（路由判断 → 原子主张提取 → 科学问题 `science_claim_audit`），主张按 supported/uncertain/human_review 标记，高影响主张缺权威一手来源强制 human_review；来源随回复展示并入库 `message_sources`。风险分级用规则 + 语境排除（如“小说/朋友/他说”等否定引用）。单条撤回立即生效且审计只保留不可反推正文的哈希（`memory_withdrawals`），全量删除二次确认。⚠️【待补】真实案例截图与人工复核记录。
- **目前仍存在的主要局限**：见 P19。核心包括：不做诊断、不替代专业判断；模型推断类记忆需确认才生效（承认会猜错）；科学审计基于传入来源做确定性检查，不联网不调模型，覆盖面有限；部分人群/场景/文体未覆盖；向量或科学审计服务不可用时明确降级或转人工复核；演示模式（NO_DB_MODE）数据易失、费用为估算。

## P2｜作品目标与实际完成内容

### 团队实际解决的问题

长期陪伴场景中，现有 AI 回答普遍存在“每轮都友善、却始终没有积累出真正的了解”的断裂：模型记不住用户说过什么，分不清此刻该倾听还是该给建议，用户也无法确认“你记对了没有”或撤回被记错的内容。在科普与科学表达场景中，AI 又倾向于用“温暖”包装不确定的陈述，把缺乏依据的结论说得像事实。知微希望解决的是其中可工程化的一环：**让“越来越懂用户”成为有授权、有证据、可撤回、可量化验证的系统行为，同时保证所有“有温度”的表达不牺牲事实准确与分寸。**

### 本作品实际完成的工作

（均已实现，不含未完成项）
- 对话主链路：风险分级 → 记忆/画像检索 + 向量化 → 上下文编译 → 事实路由 → 流式回复 → 后台反思落库；
- 记忆生命周期：短期（绑会话、约 7 天过期）与长期分治；候选确认/编辑/撤回（完整链路在 review 分支）；
- 8 维动态画像综述 + 维度权重 + 理解度分数（覆盖/验证/个性化/时效）；
- Personal Skill：结构化“相处方式”整体重写与版本发布（表达/关注/节奏三维）；
- onboarding 动态问卷（答满 3 题进入聊天）、会话标题、心情样本与曲线、站内回访提醒；
- 事实查证与科学审计：来源保存、原子主张分级、supported 之外不当作已核实；
- 风险三路径（普通陪伴 / 澄清眼前危险 / 紧急现实支持）与隐私控制（单条撤回、全量删除、三类开关）；
- 比赛实验室（同一输入跑三种模式）与测试/评测/e2e 体系、版本化基线证据。

### 本作品形成的完整过程（总体思路，可画成图）

```
用户输入 → 风险分级 → 记忆/画像检索 + 向量化
        → 上下文编译（基底 Skill + Personal Skill + 画像 + 记忆 + 摘要 + 近 12 条消息）
        → 事实路由 / 科学审计（需要时）
        → 流式回答（带来源）→ 消息与来源入库
        → 入队后台反思：记忆提案 → 画像综述 → 会话摘要 → 心情 → 回访提醒 → 技能演化信号
        → Memory MCP 策略层校验后落库 → 用户可查看/确认/编辑/撤回
        → 反馈与理解度更新 → 下一轮更懂用户
```

- **最终给出的结果形式**：可交互 Web 端（Next.js + SSE 流式），含对话界面、画像/记忆侧栏、开发面板（记忆/画像/技能/费用/trace）、比赛实验室、隐私控制（记忆开关/撤回/全量删除）。
- **已处理的任务与场景**：日常陪伴、情绪倾诉与倾听、科普式科学问答、课程讲稿式写作；中文为主。
- **相较通用模型直接回答最主要的不同**：通用模型是“无状态单轮友善响应”；知微是“有记忆但克制”的系统——模型可推断但长期记忆需确认才生效；画像是一段带证据、可演化的综述而非标签列表；所有表达先过风险与事实闸门，宁可承认不确定也不用“像人”包装不准确。

## P3｜本作品所说的“人味”与“温度”是什么

| 要回答的问题 | 实际填写内容 |
|-------------|-------------|
| 选择维度 | A（数字分身/长期陪伴）为主，结合 B（表达自然度）与事实准确要求 |
| “人味/温度”指什么 | 不是语气词/表情/自称堆出来的拟人感，而是三个可验证的承诺：①有记忆但克制——短期与长期、推测与确认分开，用户对“系统怎么记住自己”全程可见、可改、可撤回；②理解但不标签化——画像是一段随证据变化的人物综述 + 维度权重，理解度由覆盖、验证、反馈、时效共同计算，不把一次表达固化成性格、不预测人生走向；③有温度但不失准——科学/事实问题先审计证据与原子主张再决定语气与结论强度 |
| 最终输出什么 | 流式对话回复（可带来源标注）、用户画像综述（维度权重 + 理解度分数）、待确认候选与已生效记忆列表、Personal Skill 版本、情绪趋势曲线、会话标题、站内回访提醒 |
| 不能说明什么 / 不能用于什么 | 不能说明系统具备真正的理解或共情；不能用于专业医疗诊断、心理评估、法律咨询、生涯决策；不能替代专业人员；不能对用户做自动化性格分类或行为预测 |

### 使用边界

- **适用场景**：愿意被长期了解、但不想被标签化的普通匿名用户；日常陪伴、轻度情绪倾诉、科普问答、讲稿写作辅助。
- **必须准确克制的表述**：可验证的科学事实/数据/时间/地点/人物身份；健康症状、用药、治疗相关任何表述（不做医学归因，必要时提示就医）；法律权利与后果、财务投资建议等确定性表述（不给确定结论）。
- **情绪/健康/生涯的处理规则**：情绪话题以倾听与承接为主，不强行归因；身体不适作为用户正在经历的事实回应，不做诊断、不把不适武断归因于压力；生涯话题以澄清为主，用户明确求建议时给“明确但可修正”的意见；紧急信号（自伤/伤人）走紧急现实支持路径并给出求助指引。
- **必须由用户本人或专业人员判断**：是否需要就医、诊断与治疗方案；法律行动；职业与人生重大决定；涉及他人隐私或利益的内容。

> “人味”和“温度”以事实准确与用户授权为前提；流畅、亲近或风格化不能代替准确性，也不能代替专业判断。

## P5｜验证方案与成功标准

| 要验证的问题 | 判断方法 | 测试对象/样本 | 算通过 | 算失败/无法判断 |
|-------------|---------|--------------|-------|----------------|
| 是否越来越懂用户（维度 A） | 记忆分类 F0.5 评测 + 理解度分数逐轮趋势 + 人工一致性检查 | 11 条固定语料 + 团队多轮测试对话（Scripted 与真模型双模式） | F0.5≥0.7；多轮后理解度上升；画像与历史一致 | F0.5<0.5；理解度不变化/下降；画像明显矛盾 |
| 是否更自然、少模板腔 | Scripted 基线 vs 真模型输出对比；比赛实验室三模式；人工偏好 | 同输入三模式输出 | 人工偏好有画像/个人版本比例 >60%（拟定阈值，需真实盲评） | 更“机械”或过度热情；结构化频繁校验失败 |
| 事实与分寸是否可靠 | supported/uncertain/human_review 分级；来源可追溯；高影响缺权威源强制 human_review | 团队构造 ≥10 个科学问题（含可验证/有争议/依据不足三类） | supported 有对应引用；uncertain 语气降级；human_review 不给确定结论 | supported 无引用；uncertain 用确定语气；human_review 被当已核实 |
| 反馈后是否持续改进 | 画像重算、技能演化、理解度记录 | 含纠正/撤回的多轮对话 | 纠正后画像较快体现；撤回记忆不再参与回答；技能版本随风格演进 | 纠正后多轮不变；撤回记忆仍出现；演化后劣化 |

> 注：上表“算通过”的阈值（F0.5≥0.7、>60% 等）是团队拟定的验证目标，不是系统内置门槛；P14–P16 需填真实结果。评价者安排（团队成员盲评/外部人员/真实用户、独立性说明）⚠️【待补】。

### 完整过程说明（以“记住用户喜欢科幻”为例）

1. 用户发送“我最近在读《三体》，特别喜欢科幻那种宏大感”：`POST /api/conversations/[id]/messages`，携带匿名 cookie userId。
2. `assessRisk` 判定 ordinary；消息入库；系统并行做向量嵌入、检索当前画像/记忆/摘要/技能，编译上下文。
3. 网关按普通陪伴协议流式回复并入库；回复完成后入队 `reflection` job（异步，风险回合不触发）。
4. Worker 反思：重编译上下文 → `reflect`（需要深审则 `deep` 二轮）→ 产出记忆提案（类别 interest、content、evidence 消息 ID、confidence、tier），并经语义去重过滤。
5. Memory MCP 策略层校验归属/重复/敏感后落库：**长期候选进入 pending（待确认），不参与回答与画像**；短期信息按会话作用域 active。
6. 需要时 Worker 调用 `synthesizeProfile` / `summarizeSession` / `generateReturnNote`（仅基于已生效内容；回访 6 小时后生效、3 天过期）并为新记忆生成向量。
7. 用户在画像栏看到“待确认候选”→ 点击盾牌确认（或铅笔编辑）→ 该记忆转为 active → 系统重算画像快照与理解度 → SSE `memory.updated` 推送，前端实时刷新。
8. 后续用户问“推荐点类似的科幻小说”：检索命中该 active 记忆并注入上下文，模型据此选择内容与分寸（不罗列“我查到了什么”）。
9. 用户若说“那只是随口一提，我更喜欢历史”：反思检测冲突 → 生成 supersede 提案（新认识 pending）→ 确认后旧版停用、新版生效，后续不再偏向科幻。

### 一次真实上下文示例（示意性脱敏，非某次运行原文）

```
<skill name="zhiwei-persona" version="1.0.0">…</skill>
<skill name="scientific-answering" version="1.0.0">…</skill>
（中文规范段：科学表达按受众认知搭桥；类比必须准确并说明边界；先承接问题…）

个人相处方式：{...PersonalSkill JSON...}
人物综述：…（当前用户画像文本，⚠️ 数字仅为示意）
相关认识：[{category:"interest", content:"…", tier:"long", confidence:0.85, ...}]
会话摘要：…
已核事实简报：{claims:[{text,status:"supported",sourceIndices:[1,2]},…], summary:…}  ← 只能确定陈述 supported

输出要求（科学）：{"content": string(≤8000), "claimIndicesUsed": number[](⊆supported 索引), "analogy": {"text","boundary"}|null, "distinctions": string[](≤8)}
```

- **减少模板腔/空话/过度推断**：基底 Skill 明确避免模板腔、空话、过度排比与“先承接再升华”的机械结构；温度差异化（0.58/0.38/0.32）；结构化 schema 限死字段；Scripted 基线用于对照真模型是否出现模板腔膨胀。⚠️ 不要声称技能“禁止 首先/其次/最后 字样”——代码未内置该词表。
- **画像/风格进入上下文而不压倒事实**：画像与技能只是上下文素材，科学任务中 `已核事实简报 + claimIndicesUsed⊆supported` 构成硬约束；类比必须写 boundary；画像再“热情”也不能引用 unsupported 主张。
- **该设计带来的变化**：⚠️【待补】真实对照（比赛实验室三模式输出），避免写“3 轮后提升/相关性提升”等未实测结论。

## P8｜维度 A：画像如何记录与更新（记忆生命周期）

### 画像内容与生命周期

| 画像内容（举例） | 什么时候记录 | 什么时候更新 | 什么时候用于回答 | 用户如何查看/修改/撤回 |
|---|---|---|---|---|
| 基础信息（称呼、所在城市、职业/学业、年龄范围） | 用户明示或 onboarding 问卷回答时（`user_stated` 仅在能从证据原文定位时成立） | 用户新信息产生 supersede 提案，确认后替换旧版 | 称呼、内容选择、分寸 | 画像栏查看；编辑生成新版本；撤回停用 |
| 目标/兴趣/表达/情绪/经历/挑战/边界等 | 反思器从消息提出 0–2 条候选，绑定本会话证据；明确“记住/以后记得”标 explicit | 用户确认/编辑→active；冲突→supersede 新版本；撤回→withdrawn；到期→expired | 只有 active 长期记忆进入检索与画像 | 同上；`boundary` 类约束（“别再提/别追问”）即时生效 |
| 模型推断的长期认识 | 一律先 pending（候选），不用于回答与画像 | 用户确认（confirmed/accepted）或编辑后才 active | 确认后进入回答上下文 | 盾牌=确认、铅笔=编辑、撤回按钮=停用 |

### 关键规则（与 `docs/memory-lifecycle.md` 一致）

- 短期记忆固定作用域 `episode+conversation`、绑来源会话、最长约 7 天过期、**绝不进入跨会话画像**；长期记忆类型 profile/learning/misconception。
- 检索只读“当前用户、未过期、已生效、作用域一致”的版本；短期不跨会话召回；pending 不参与回答与画像。
- 画像综述只综合已生效记忆已明确表达的事实，不补写性格、动机、身份认同或潜在困惑；不生成“了解度百分比”以外的确定性人格描述。
- “短期上下文”与“长期记忆”有独立开关；关闭一项不影响另一项；记忆关闭后不再检索、不生成持久摘要、不写新画像。
- 否定指令（“不要记住”）不会被误判为保存请求；撤回后的内容指纹阻止旧后台任务重写同一内容；用户撤回后明确要求可重新建立。

### 维度 B 说明（模板腔 / AI 味）

知微以 A 为主，未实现独立的“模板腔检测器”；B 维度通过基底 Skill 的表达规则、结构化 schema 与温度控制、以及 Scripted↔真模型对照来“识别与改善”模板腔/空话/过度排比。如评委要求 B 表格，建议如实按“表达规则 + 对照验证”填写，不虚构独立识别模型。

## P9｜画像如何参与回答 / 表达如何改善

### 维度 A：画像在回答中的作用与防越界

- **实际作用**：称呼与话题优先级（Personal Skill 的 priorityTopics / longTermConcerns / unfinishedThreads）、建议分寸（directness/adviceTiming/brevity）、是否追问（questionFrequency/followUpStyle）、是否用记忆（只在不突兀时自然使用，不罗列“我查到了什么”）。
- **防止越界推断/刻板印象**：①只有 active 长期记忆进上下文；②综述只写已表达事实，不预测职业/关系/价值观/心理问题；③理解度把“模型置信度”当弱先验，跨会话稳定与用户确认才是强信号；④修正会显著惩罚 validation 分量；⑤`boundary` 类记忆（别再提/别追问）即时约束。
- **冲突/过期/否认**：supersede 与编辑生成新版本、旧版停用；撤回即停用；用户否认后相关记忆停止参与回答；全量删除二次确认。

### 维度 B：表达如何改善（如实描述）

- **实际采用方式**：基底 Skill 表达规则（倾听/建议时机、承接篇幅、课堂讲稿开场规范等）+ 结构化 schema + 分任务温度 + Scripted 确定性基线对照，而非模型微调或独立风格检测器。
- **如何保持事实准确与场景适合**：科学/写作任务硬约束“只能确定陈述 supported、类比必须说明边界”；健康/法律/财务不做确定断言；风险规则优先于篇幅要求。
- **改善前后变化**：⚠️【待补】真实“同输入三模式”输出对比与人工评价记录。

## P10｜事实可靠与表达分寸

- **核对什么**：时效事实（新闻/价格/规则等）与科学问题；可验证陈述按原子主张拆解并标注来源。
- **怎么核对**：`routeFacts` 路由 → 需要时 `buildFactBrief`（Qwen 生成主张+来源索引，来源随回复保存展示）→ 科学问题再经 `science_claim_audit` 确定性分级；高影响主张缺权威一手来源（gov/edu/who 等或原始研究）强制 human_review；越界来源索引移除。
- **依据不足时怎么表达**：uncertain/human_review 主张必须以不确定语气表述；不依据 summary 补造事实或来源；明确提示“该结论依据不足/建议咨询专业人士”。
- **哪些不能写成确定说法**：医疗诊断/用药/治疗建议、法律后果、财务投资建议；无一手权威来源的科学高影响主张；任何未经验证的“人味”断言。
- **情绪/健康/生涯规则**：区分科学事实、个人观点与安慰性表达；身体不适只作为用户经历的事实回应；紧急信号给现实求助提示；用户明确求建议时才给“可修正的意见”。
- **错误处理**：Science MCP 不可用 → 相关主张一律降级 human_review，不留“已核实”假象。

## P11｜质量控制、异常处理与人工介入

- **结构校验**：所有结构化输出过 zod schema；非法/质量不达标触发网关重试契约（`aliyun-contract.test.ts` 覆盖）。
- **不静默降级**：真实模式下失败不会退回 Scripted 仿真回答；错误按码映射为友好提示（rate_limited / provider_unavailable / invalid_response / request_cancelled / provider_authentication_failed 等）。
- **降级路径（明确的）**：dialogue→background 模型回退并重试；向量服务不可用→关键词检索并记录 degraded；科学审计不可用→human_review。
- **反思防护**：单轮记忆提案上限 2 条、同类二元组重叠≥0.72 去重、goal 负向表达剔除；`needsDeepReview` 触发第二次深审。
- **留痕**：`trace_events` / `model_runs` / `mcp_calls` / `activity_events` / `risk_events` / `memory_events`（分支）全链路记录，支持人工复核；MCP 调用日志失败不把已成功业务操作误报为失败。
- **人工介入点**：human_review 状态、风险事件、撤回/全量删除审计；开发面板可视化供人工检查。

## P12｜授权、隐私与信息安全

- **身份与隔离**：匿名 cookie userId（`ANON_COOKIE_SECRET` 签名）；所有跨用户读取/撤回/删除请求必须失败。
- **授权开关**：长期记忆 / 情绪趋势 / 站内回访可分别关闭；记忆关闭后不再检索、不再生成持久摘要、不写新画像。
- **撤回**：立即停用该记忆参与回答；撤回审计仅保留类别、时间、原因与不可反推正文的哈希（`memory_withdrawals`）。
- **修改**：确认/编辑生成新版本（supersede 旧版），保留版本链供追踪。
- **全量删除**：用户输入“删除知微中的全部数据”并二次确认后，清除对话、画像、记忆、技能、情绪、反馈、索引与 Trace。
- **数据位置与期限**：本地 Postgres（pgvector），短期记忆约 7 天过期；演示模式 `NO_DB_MODE=true` 为进程内存储、重启清空，页面按演示状态对待；密钥走 `.env`，不入 git；⚠️ 分支启动脚本引用的百炼 API CSV 未被 .gitignore 覆盖，切勿提交。

## P18｜对照结果与方案优越性

- **对照机制（真实存在）**：比赛实验室对同一输入依次运行三种模式（直接回答 / 固定 Skills＋画像 / Personal Skill 演化版），记录主张、来源状态、延迟与体验偏好；风险事件与撤回审计同时留档。可用于与“通用模型直接回答/无画像版本”做同口径对照。
- **科学逻辑层面**：把“人味/温度/理解用户”落到记忆授权、非标签化画像、事实分级三个可审计界定上。
- **技术实现层面**：上下文工程（基底 Skill 只读+哈希、素材分层注入、预算截断）+“模型只提提案、策略层落库”解耦 + 统一网关（仿真/真实同构切换、费用与 trace 全覆盖）。
- **结果表现层面**：⚠️【待补】真实三模式对照输出与评价（用实验室导出）。
- **代价与不足**：⚠️【待补】如实填写（真模型延迟/费用、深审二次调用、人工复核成本、语料规模小等）。

## P19｜失败案例、局限与适用边界

| 失败/边界问题 | 实际表现 | 原因分析 | 当前处理 | 是否影响核心结论 |
|---|---|---|---|---|
| 不做诊断/不代专业判断 | ⚠️【待补】 | 设计边界 | 风险/求助路径 + human_review | 否（明示边界） |
| 模型推断会猜错 | 候选需确认才生效 | 推断固有不确定性 | pending + 用户确认/编辑/撤回 | 否（设计如此） |
| 科学审计不联网不调模型 | 只审计传入来源 | 确定性约束 | 覆盖面有限 + human_review | 需说明 |
| 部分人群/场景/文体未覆盖 | ⚠️【待补】 | ⚠️【待补】 | ⚠️【待补】 | ⚠️【待补】 |
| 向量/审计服务不可用 | 降级或转人工 | 依赖服务 | degraded/降级标记 | 否 |
| 演示模式数据易失 | 重启清空 | NO_DB_MODE | 页面标注演示状态 | 否 |

- **已支持**：匿名长期陪伴、8 类记忆、确认/编辑/撤回、科学事实分级、风险三路径、三模式对照。
- **尚不支持**：专业医疗/心理/法律/生涯判断；真实注册多用户体系；⚠️【待补】其他。
- **必须由人判断**：就医、诊断治疗、法律行动、重大生涯决策、他人隐私利益。
- **后续最需补充**：真实用户多轮语料与授权样本、更大的科学问题集、真模型对照与人工盲评记录、更广人群/文体覆盖。

> “更懂用户”或“更有人味”不等于可以替代专业医疗、心理、法律或生涯判断，也不等于对所有人群和场景都适用。
