# 记忆生命周期

知微将原始消息作为证据，由 Reflection 模型生成结构化记忆动作。模型负责正文、短长层级、近期有效期、重复与冲突判断；固定程序负责 Schema、用户范围、授权、证据归属、版本并发和写入幂等。聊天原文保存在数据库中供回看，但不会无限累加到模型上下文。

## 固定批次与证据

普通回合在同一会话累计三条用户消息，或最后一条之后空闲十分钟时，运行一次 Reflection。用户消息和批次调度记录在同一事务中写入，因此停止、断流或助手生成失败不会丢失已提交证据。批次开始后成员固定，任务重试不重新选取最新三条消息。

明确的记住、纠正、忘记指令封存相关待处理证据并立即进入后台；当前对话不等待整个记忆链完成，也不提前声称修改成功。普通批次通常输出 0–2 个动作，最多 3 个；明确多目标撤回通过连续小批处理，不截断用户目标。

Reflection 读取有序证据 `E1`–`E3`，每条包含原文和原消息时间。模型为每个动作选择真实来源及使动作成立的触发证据，系统精确映射成消息 ID。不会把三条用户输入伪装成一条文本，也不会强制把最后一条加入所有动作。上下文截止于本批末条，之后的普通消息进入下一批。

## 具体性与新增去重

只有具体、新增且对未来交流有用的信息才生成原子记忆，初识回答不保证每题产生一条。仅说“最近有点烦”“生活琐事让我烦”，未说明具体事件、对象、偏好或问题时，保留聊天原文，不生成记忆、心情、画像、会话摘要描述、回访或个人 Skill 变化。

每批按各条证据召回相关旧认识，合并为最多 12 条候选，再由一次 Reflection 同时比较批内和新旧内容：

- 没有新事实，不写入。
- 同一件事的细化，用 `supersede` 更新原根。例如已经知道购物方面的具体困扰后，不再另存一条概括性的“生活琐事烦恼”。
- 独立事件分别保留；向量相近或关键词相同本身不是合并依据。

这组 12 条候选只用于后台反思，不改变回答的 5/3 检索配额。向量和关键词负责寻找候选，模型负责正文与语义判断；新机制不触发全库或逐用户历史清理。长期阈值收拢仍使用下述独立的两阶段流程。

## 直接生效语义

| 动作 | 语义 | 固定校验 |
|---|---|---|
| `create` | 建立新的活动原子记忆 | 证据必须属于当前用户和来源会话 |
| `supersede` | 以新版本直接替代旧版本 | `memoryId` 和 `expectedVersionId` 必须命中当前活动版本，正文必须发生实质变化 |
| `promote` | 将近期记忆升级为长期记忆 | 来源必须是当前活动的近期版本，新版本清除近期期限 |
| `withdraw` | 停止使用指定活动版本 | 使用精确记忆及活动版本，并保留真正触发撤回的证据 |

合法动作不进入待确认状态。模型无法判断新信息是长期变化、暂时例外还是对旧记忆的纠正时，当轮对话自然追问，Reflection 不提交冲突动作。

每批最多生成一个有具体依据的最后整体心情，使用实际表达该情绪的证据时间，而不是后台执行时间；不机械平均三条消息。中性的身份、偏好或工作事实不因模型自报高分而进入曲线。用户明确描述希望知微如何回应时，类别为 `expression`。

## 近期与长期

- 近期记忆在同一用户的多个会话中共享。模型给出 1–30 天内的有效期；缺失、无效或越界时统一改为 7 天。
- 长期记忆不设自动到期时间，通过后续模型动作更新、升级、撤回或收拢。
- 一次回答最多编译 8 条原子记忆：长期最多 5 条，近期最多 3 条，空余名额可由另一层补齐。
- 检索依据语义相关度、中文词法和时效。模型 confidence 只用于开发诊断，不改变检索或了解度。
- 授权和用户范围在召回前过滤。长期、近期分别获取语义与关键词候选，再执行最终配额，避免大量近期条目挤掉长期认识。
- 会话滚动摘要始终属于原会话，不受近期原子记忆开关影响。

模型单独给出 `summaryEvidenceMessageIds`，只有具有具体内容的证据进入摘要整理。摘要更新与原子记忆更新是不同动作，不把没有记忆变化等同于没有会话进展。

## 撤回与因果顺序

撤回立即终止当前版本召回，不形成永久的内容禁止。撤回后的新消息再次表达相同信息时，可以建立新记忆。证据早于撤回的积压任务不得复活内容；同一条撤回消息不能同时重建对应认识。这个顺序同样适用于用户先表达事实、事实尚未落库就要求忘掉的情况。

用户可在界面按具体版本撤回，或在聊天中说明修正意图。开发者模式可恢复 `superseded`、`withdrawn`、`expired` 历史版本：行内确认后复制成新的活动版本，替代同根当前版本，保留旧版本。恢复近期版本重新赋予七天期限；恢复长期版本后重新生成长期综述。

## 长期收拢

活动长期记忆达到 48 条或估算超过 12k Token 时，后台在同类别、同主题范围内生成更少的原子表述，目标降到约 32 条或 8k Token。收拢方案会由第二次独立结构化调用核对遗漏、矛盾和过度推断。核对失败时整批不写入；成功时使用版本 CAS 和单一事务替换来源版本，并合并证据关系。

## 长期认识与了解度

- “关于你的长期认识”只综合活动长期记忆，不写入 `emotion` 和 `boundary` 内容。
- 证据较少时保持 80–250 字；信息充足后使用 300–600 字、2–4 个自然段。
- 画像快照保存完整来源记忆版本集。源集与当前活动长期版本不一致时，回答只使用原子记忆，不使用过期长文。
- 了解度只使用活动长期记忆。近期记忆、消息数、使用时长、连续登录和 confidence 不直接加分。
- 三道包含具体信息的初识回答按约 5%–10% 校准，但题数本身不加分，无有效长期记忆时不设置分数下限；单次会话最高 25%，总分最高 95%。
- 未授权维度移出评分分母。`boundary` 计入覆盖，关闭情绪后 `emotion` 移出。
- 空权重采用完整八维默认值，已经根据授权缩小的维度集合不会被重新补全。替代属于中性更新，不把正常变化一律当作纠错扣分。
- 初识的覆盖成熟度有独立会话约束，模型将权重集中到少数已知维度不会抬高初识分数；后续通过独立会话逐步放开，而不是按答题数加分。

## 授权与回答上下文

匿名用户由服务端签名 Cookie 识别，客户端不能指定或切换任意用户 ID。Web 和 Worker 经 Memory MCP 读取、写入记忆、画像及个人 Skill，工具参数不接受模型指定的用户范围。

左下角“设置”集中管理总记忆、近期、长期、情绪、相处方式、站内回访及当前用户全量数据删除。总开关只暂停，不改动两个分层偏好；恢复时沿用原组合。关闭某层后停止该层新增和召回，但旧数据仍可查看；总记忆或长期暂停时保留上次了解度并标注暂停。关闭情绪后停止心情样本和 `emotion` 类记忆的新增与召回。

回答上下文使用最近有界消息、原会话摘要、同步的长期综述、最多八条原子记忆、当前个人 Skill 和所需基底 Skills，超预算按区块缩减，不退回完整聊天历史。展示界面可以读取最近一次长文；对话只能使用与当前来源版本一致的长文。

助手重试只创建新的回复尝试，不重复提交原用户消息，也不再次触发记忆学习。普通界面显示当前尝试，旧尝试保留在开发者记录；重生成成功后可重新整理本会话摘要。

## 审计与补偿

`memory_events` 记录创建、替代、升级、撤回、过期、实际加入上下文、收拢、向量补齐和开发者恢复；`memory_operations` 保留幂等操作结果。快照来源、版本血缘及逐动作证据可在开发者模式追溯。

向量失败不阻止合法记忆生效，先使用关键词检索，后台幂等任务只向仍然活动的目标版本补写向量。画像失败保留最近可靠快照并重试；来源不同步的旧快照只用于展示，不进入回答。MCP 审计落库失败不改变已经成功的业务结果。

Activity 通过进程共享的 PostgreSQL 通知监听唤醒，配合持久事件游标补读；Worker 根据通知和任务到期时间调度，问卷规划与顺序记忆链分别处理。单 Worker 重启恢复遗留任务，退出传播取消；批次、记忆动作和个人 Skill 重写使用各自幂等键，避免恢复或重试重复写入。数据库变更只使用前向迁移，不通过替换数据卷升级。
