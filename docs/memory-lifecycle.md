# 记忆生命周期

知微将原始对话作为证据，由模型产生结构化的记忆提案。模型不能直接决定提案的作用域、生效状态或用户归属；这些由 Memory MCP 后的固定策略层处理。

## 状态流转

| 场景 | 初始状态 | 用于回答 | 用于画像 | 后续动作 |
|---|---|---:|---:|---|
| 当前会话的普通短期信息 | `active` | 仅来源会话 | 否 | 到期后 `expired` |
| 用户明确陈述的普通长期信息 | `active` | 是 | 是 | 可撤回或在对话中修正 |
| 需要推测的长期信息 | `pending` | 否 | 否 | 用户确认或拒绝 |
| 对已有记忆的修正或升级 | `pending` | 旧活动版本继续生效 | 旧活动版本继续生效 | 确认后生成新活动版本 |
| 用户确认候选 | 候选变为 `accepted` | 新建的 `active` 版本 | 新建的 `active` 版本 | 重建画像快照 |
| 用户拒绝或撤回 | `rejected` / `withdrawn` | 否 | 否 | 保留不可召回的历史与内容指纹 |

## 不变量

- 所有证据消息必须同时属于当前用户和当前会话。
- `user_stated` 只在 `evidenceQuote` 能从证据原文中定位时成立；否则降级为 `inferred`。
- 短期记忆的 `scopeKey` 由服务端注入，有效期不超过 7 天。
- 正常检索只返回 `active` 版本；待确认候选只能通过管理读取获得。
- 状态写入使用记忆根 ID、具体版本 ID 和幂等键。旧版本发起的操作会以版本冲突结束，不发生局部写入。
- 画像和了解度只使用已生效的长期记忆。
- 撤回后的内容指纹会阻止旧后台任务重新写入同一内容；用户在撤回之后明确要求重新记住时可以重新建立记忆。

## 审计与失败语义

`memory_events` 保留候选创建、确认、替代、拒绝、撤回、过期和实际加入上下文的事件。`memory_operations` 保留幂等操作结果。MCP 调用日志失败不会将已成功的业务操作误报为失败；无效结构、证据越界和版本冲突都不会写入业务数据。
