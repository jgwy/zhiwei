# 长期记忆生命周期（赛道三·XH-202619）

知微把“记住什么”与“是否允许使用”分开管理。每条记忆包含来源、范围、敏感级别、重要性、记忆类型、证据摘录和版本链，用户可以在画像栏查看并执行确认、编辑或撤回。

## 短期与长期的职责边界

- 短期记忆只保存当前会话仍需继续使用的临时事件，固定为 `episode + conversation`，必须绑定来源会话，最长七天后过期，绝不进入跨会话画像。
- 长期记忆只保存跨会话稳定信息，类型为 `profile`、`learning` 或 `misconception`。模型推断的长期记忆先进入 `pending`，确认前不会用于回答或画像；用户明确要求记住、用户确认或编辑后才进入 `active`。
- `learning` 记录有证据的掌握状态与学习进度；`misconception` 记录具体概念误区及正确区分，不能仅因用户提出问题就推断其不懂。
- 短期上下文和长期记忆拥有独立开关，关闭一项不会影响另一项。

## 生命周期

1. 对话反思器从当前用户消息提出 0–2 条候选认识，并必须绑定当前会话中的证据消息。
2. 系统校验证据归属、敏感信息和重复内容后按短期/长期策略写入。明确“记住/以后记得/请保存”时标记为 `explicit`；用户确认或编辑后标记为 `confirmed`；模型谨慎推断标记为 `inferred`。否定指令（例如“不要记住”）不会被误判为保存请求。
3. `supersede` 和用户编辑会停用旧版本并生成新版本；撤回会停用活动版本并写入撤回记录。
4. 检索只读取当前用户、未过期、已生效且与当前会话/项目作用域一致的版本。短期记忆不能跨会话召回，待确认长期记忆不能参与回答。排序综合语义相关性、词面相关性、置信度、长期层级、重要性和确认新鲜度；敏感级别不会带来额外召回加分。
5. 每次实际召回会更新 `last_used_at` 并写入 `used` 事件；`memory_events` 还记录 created、updated、confirmed、promoted、superseded、withdrawn、expired 等事件，便于复现和人工复核。

## 用户控制

- 画像栏分开展示待确认候选与已生效记忆，并显示记忆类别、用途类型、长期/短期、作用范围和来源标签。
- `盾牌`按钮确认候选；`铅笔`按钮直接编辑并生成确认版本；`撤回`按钮停用该认识。
- “短期上下文”和“长期记忆”可分别关闭；“删除全部数据”仍走全量删除流程。

## 数据库与 localhost 演示

- 数据库模式使用 `packages/core/migrations/007_memory_lifecycle.sql`，需执行 `npm run db:migrate`。
- `NO_DB_MODE=true` 时使用进程内演示存储，支持同样的查看、确认、编辑、撤回闭环；重启 Node 进程后数据会清空，页面应将其视为演示状态，不等同于持久化部署。
