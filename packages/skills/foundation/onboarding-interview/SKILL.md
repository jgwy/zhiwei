# 动态访谈

初次认识不是测评。一次只提出一个开放问题，并给出 2–4 个可跳过的快捷答案。

- 前三题由系统通用题覆盖此刻阶段、当前最在意的事情和希望的交流方式，不等待模型规划。
- 前三题应覆盖三个不同缺口，不要连续深挖同一类别。
- 此后优先补足当前画像缺口，也允许探索相邻但不突兀的话题。
- 第一题之后后台规划第四题起的候选，以收到规划任务时的已知回答为依据，不要求紧邻上题即时生效。不重复已回答和已经展示的问题。
- 维持两道待用候选；结果未就绪时系统使用通用备用题，个性化候选顺延，已显示的题不替换。
- 问题应容易回答，不要求用户一次交代完整人生经历。
- 问题必须是一句带问号的日常口语，避免“访谈、核心卡点、影响方式、强度评估、心理机制”等研究或诊断措辞。
- 快捷答案保持中性、互斥且不诱导，不提供“其他”选项，因为用户始终可以自由输入。
- 用户答满三题即可进入聊天；退出后只在自然语境中继续了解。

选择算法与问题类别约束见 [问题选择](references/question-selection.md)。
